## Committed lesson continuation

Business state `lessonAdmission` retains proposalDirectory,
lessonSourceDirectory and lessonId. Optional `methodSource` is a bounded
{path,sha256} reference to the exact historical method bytes. Obtain them from
the stated method Git revision; do not substitute current guidance or rewrite
old exports. The native gate compares the proposed methodDigest to these bytes,
preserves them in reviewed-method-source.md, and records
methodCommitAuthenticated=false. Native hash comparison is not Git provenance
authentication. Without this option the existing current-method requirement
still applies.

Optional `committedReturn` requires reviewed=true, `knowledge`
{directory,cutSha256,revision}, `guidanceSelection` {path,sha256}, and `readback`
{path,sha256}. Ordinary lesson reconstruction and strict staging run first.
The readback schema `agentlab.reviewed_lesson_committed_readback.v1` contains:

- knowledgeRepository, previousRevision, revision;
- before and after complete table-status responses, clean at revision;
- tables: all five original knowledge table-query responses;
- lessonSource: repository, revision, tablePrefix and every original operational
  table-query response declared by the selected lesson export.

Rows must be complete, untruncated, uniquely keyed and at the exact revision.
Knowledge uses the existing payload envelope; operational rows are direct.
All committed knowledge rows must equal the reconstructed stage, with exact
assessed JSONL bytes, source inventory, assessment and inherited operation
evidence in the next cut. The source readback must reproduce all exported lesson
rows. No status-only PASS, missing sidecar, dirty bracket, borrowed source or
unchanged knowledge revision can advance state. Captures remain unauthenticated
at this byte-level gate; the operator owns live transport capture.

The next explicit selection must include the admitted Skill and pass the ordinary
guidance applicability gate. The adapter then reports completed, rebinds knowledge
and guidance, retains priorRoundEvidence, and removes old operationCapture,
operationExecution, behaviorExecution, lessonAdmission, observationPersistence
and candidateId. The next round must produce new work; old captures cannot run
again merely because the knowledge hash changed. No remote transaction is issued
by this continuation mode. A future transport adapter must preserve reviewed
admission, fixed-baseline atomic writes and uncertain-write reconciliation.
